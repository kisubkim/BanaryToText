# BinaryToText

알 수 없는 바이너리 파일을 사람이 읽을 수 있는 텍스트로 바꾸는 **오프라인 데스크톱 앱**입니다 (Windows, PySide6).
브라우저나 네트워크 없이 동작합니다.

해독 방식을 모르는 파일도 다룰 수 있게 만들었습니다. 파일을 열고, 자동 분석으로 단서를 얻고, 규칙을
하나씩 추가하면 결과가 바로 다시 해석되어 텍스트로 나옵니다.

**화면과 함께 보는 사용설명서: [docs/manual.md](docs/manual.md)**

## 실행

| 방법 | 명령 |
|---|---|
| 배포 exe | `dist\BinaryToText.exe [파일]` (GUI), `dist\btt.exe` (명령줄) |
| 소스 | `.venv\Scripts\python -m binarytotext [파일]` |
| 빌드 | `powershell -ExecutionPolicy Bypass -File build.ps1` (테스트 후 아래 결과물 생성) |

빌드 결과 (`dist\`):

| 결과물 | 용도 |
|---|---|
| `BinaryToText.exe` | GUI 단일 exe. 내 PC에서 쓰기 편한 형태 |
| `btt.exe` | 명령줄 단일 exe (Qt 없음, 표준 라이브러리만) |
| `BinaryToText\` | GUI 폴더형. Qt DLL 이 따로 있어 교체 가능, 라이선스 고지·`btt.exe` 포함 |
| `BinaryToText-<버전>-win64.zip` | 폴더형을 압축한 것. **다른 사람에게 배포할 때는 이것을 쓰세요** |

옵션: `-SkipTests` (테스트 생략), `-SkipOneFile` (GUI 단일 exe 생략).

## 결과 내보내기

툴바 **텍스트 저장 (Ctrl+S)** 은 저장 창에서 원하는 폴더와 파일 이름으로 저장합니다
(기본값은 원본 옆의 `원본이름.확장자.txt`, UTF-8). 화면에는 최대 20만 줄까지만 보이지만 저장 파일에는 전체가 들어갑니다.
**JSON 저장** 은 오프셋·길이까지 담은 트리를 저장합니다. 명령줄은 `-o 파일이름` 으로 지정합니다.

### 여러 파일 한 번에 변환 (Ctrl+B)

툴바 **여러 파일 변환** 을 누르거나, 창이나 `BinaryToText.exe` 아이콘에 파일 여러 개 또는 폴더를 끌어다 놓습니다.

- 해석 방식은 **지금 화면의 설정**(사용자 규칙 또는 내장 포맷과 그 옵션, 전처리, 오프셋/원본 hex 표시)을 그대로 씁니다.
  규칙 폴더가 지정돼 있으면 **파일마다 식별 조건이 맞는 규칙 세트를 자동 선택**하고,
  맞는 것이 없는 파일은 현재 화면 설정으로 변환하거나 건너뜁니다(선택).
- 폴더를 넣으면 그 안의 파일을 고릅니다. *하위 폴더 포함* 을 켜면 출력 폴더에도 같은 폴더 구조로 저장하고,
  *폴더에서 고를 파일* 에 `*.bin;*.dat` 처럼 패턴을 줄 수 있습니다. 출력 폴더 안의 파일은 다시 고르지 않습니다.
- 출력 폴더를 비우면 각 원본 옆에 저장합니다. **파일 이름** 형식: `{name}` = 원본 이름(확장자 포함),
  `{stem}` = 확장자 뺀 이름, `{ext}` = 확장자. 예: `{stem}_해석.txt`. 형식은 텍스트 또는 JSON.
- 같은 이름이 이미 있으면 기본으로 `이름 (2).txt` 로 저장합니다(덮어쓰기 선택 가능). 원본 파일은 절대 덮어쓰지 않습니다.
- 결과 표에 파일마다 상태(완료/건너뜀/실패), 쓰인 규칙·포맷, 해석률, 저장 위치가 나옵니다.
  한 파일이 실패해도 나머지는 계속 변환합니다. 줄을 두 번 클릭하면 그 원본을 메인 창에서 엽니다.

## 화면 구성

- **왼쪽 hex 보기**: 주황색 = 아직 어떤 규칙에도 맞지 않은 byte, 파란색 = 선택한 항목.
  바이트를 선택하고 우클릭 → *태그로 규칙 추가*.
  아래 **데이터 해석기**는 커서 위치의 값을 uint/int(8~64, LE/BE), float, varint, Unix 시각, BCD,
  ASCII/UTF-8/CP949/UTF-16 으로 한꺼번에 보여 줍니다.
- **가운데 탭**: 규칙 / 포맷 옵션 / 자동 분석
- **오른쪽 결과**: 텍스트와 트리. 텍스트 줄을 클릭하면 hex 위치가, hex 를 클릭하면 해당 텍스트 줄이 표시됩니다.
- 툴바: 해석 방식(사용자 규칙 또는 내장 포맷), 전처리, 텍스트·JSON 저장, 출력 모양:
  오프셋 / 원본 hex / **이름**(끄면 라벨 없이 값만) / **따옴표**(끄면 문자열을 따옴표 없이) / **쉼표**(그룹 안 항목 뒤) / **그룹**(줄마다, 배열만 한 줄,
  한 줄로). 그룹 규칙마다 *그룹 표시* 로 따로 정할 수도 있습니다. 출력 모양은 저장 파일에도 적용됩니다.

## 사용자 규칙

"이 byte(들)가 나오면 그 다음을 이렇게 읽는다"는 규칙의 목록입니다. 파일을 앞에서부터 읽으면서
가장 긴 태그가 맞는 규칙을 적용하고, 맞는 규칙이 없으면 미해석 byte 로 모읍니다.

**태그**: `09`, `5F 20` (여러 byte), `0A??` (`??` = 아무 byte), `"STR"` (ASCII 그대로)

**동작**

| 동작 | 의미 |
|---|---|
| 값 읽기 | 태그 다음의 필드들을 읽어 `이름: 값` 한 줄로 출력. 필드가 없으면 이름만 출력 (1 byte → 글자) |
| 그룹 열기 | 배열·구조체 시작. 안쪽은 들여쓰기. **닫는 태그**(예: `00`)를 지정하면 그 그룹이 가장 안쪽일 때만 닫기로 인식하고 다른 규칙보다 우선합니다. 그래서 같은 `00`이 다른 곳에서는 값이나 패딩으로 남습니다 |
| 그룹 닫기 (공통) | 닫는 태그가 없는 그룹 중 가장 안쪽 것을 닫음 |
| 그룹 열기/닫기 토글 | 같은 태그로 열고 닫음 (`0A ... 0A`) |
| 길이 블록 | 첫 필드가 길이. 그만큼을 그룹 안쪽으로 해석 (TLV) |
| 개수 블록 | 첫 필드가 항목 수. 그만큼의 항목을 그룹 안쪽으로 해석 |
| 해석 종료 | 여기서 멈춤 |

**필드 타입**: 정수(1~16 byte, 부호, 엔디언, 10/16/2진 표시, 값 이름표 `1=ON`), 실수(2/4/8),
불리언, 종료 byte 까지의 문자열(종료 byte 지정 가능, UTF-16 은 `0000`), 고정 길이 문자열,
길이 접두 문자열(1/2/4 byte 또는 varint), 바이트(hex), BCD, varint, zigzag varint, Unix 시각(초/밀리초),
건너뛰기, 나머지 전부. 문자 인코딩은 ASCII, UTF-8, CP949/EUC-KR, UTF-16, Shift-JIS, GBK, Big5 등.

**키 = 값**: 값 읽기 규칙에서 *키* 를 체크하면 읽은 문자열이 바로 다음 항목의 이름이 됩니다.
`09 "volume" 00 04 1E` → `volume = 30`. 키 다음에 같은 규칙이 또 나오면 그것은 값으로 읽습니다.

**헤더 / 꼬리 (위치 기준 구조)**: 규칙 탭의 *헤더 / 꼬리…* 에서 태그와 상관없이 파일 맨 앞부터 읽을 필드(헤더)와
맨 끝의 고정 크기 필드(꼬리, 예: CRC)를 정의합니다. 태그 규칙은 그 사이(본문)에만 적용되므로, 꼬리의 byte 가
본문 규칙에 잘못 걸리지 않습니다.

**규칙 폴더 (파일별 규칙 세트 자동 선택)**: 규칙 세트마다 *식별 조건*(위치 + byte 값, 예: 위치 0 = `FE CA`,
`??` 와 `"BDAT"` 사용 가능)을 넣고 그 JSON 들을 한 폴더에 저장한 뒤 규칙 탭의 *규칙 폴더*로 지정합니다.
파일을 열면 식별 조건이 맞는 규칙 세트가 자동으로 적용됩니다. 여러 개가 맞으면 고정 byte 가 더 많은(더 구체적인)
조건이 이깁니다. 현재 규칙에 저장하지 않은 변경이 있으면 바꾸기 전에 저장 여부를 묻습니다.
*현재 파일 값* 버튼은 열린 파일의 그 위치 4 byte 를 식별값으로 넣어 줍니다.

**규칙에 안 맞는 byte** (헤더, 꼬리, 모르는 구간)는 버리지 않고 제자리에 `?? N byte: hex |ASCII|` 로 출력합니다.
'규칙에 없는 byte' 설정으로 표시 방식을 고릅니다: 앞 32 byte 미리보기(기본) / 전체 hex 덤프(16 byte씩 줄바꿈) /
byte 수만 / 그 자리에서 해석 중단. hex 화면에서는 주황색으로 표시됩니다.

규칙 세트는 JSON 으로 저장·불러오기 합니다 (`examples/` 참고). 창에 JSON 파일을 끌어다 놓아도 됩니다.
마지막 규칙 세트는 자동으로 기억됩니다.

## 내장 포맷 (이미 알려진 방식)

| 계열 | 포맷 |
|---|---|
| TLV | 범용 TLV/LTV/LV (태그 1/2/4, 길이 1/2/4/BER/varint, 엔디언, 헤더 포함 여부, 중첩 추정), BER-TLV·ASN.1 DER/BER (X.509 인증서, PEM 자동 변환, OID 이름), EMV/스마트카드 BER-TLV (태그 사전) |
| 직렬화 | Protocol Buffers (스키마 없이), MessagePack, CBOR, BSON, UBJSON, Bencode, Thrift Binary, Thrift Compact |
| 기본 | Hex 덤프, 문자열 추출 (ASCII/UTF-8/UTF-16/CP949) |

**전처리**: 앞 N byte 건너뛰기, zlib/raw deflate/gzip/bzip2/xz 압축 해제, Base64·hex 텍스트 → 바이트, XOR(키 hex).
전처리를 쓰면 오프셋은 변환된 데이터 기준입니다.

## 자동 분석 (F6)

- 엔트로피 (압축/암호화 여부 추정), 파일 시그니처 40여 종, 가능한 전처리
- 반복 주기 → 고정 길이 레코드 크기 후보
- 모든 내장 포맷을 시도해 적합도 순으로 정렬 → 더블클릭으로 바로 적용
- **태그 후보**: 문자열 바로 앞에 반복해서 나오는 byte 를 찾아 규칙을 제안
  (`00 종료 문자열`, `1 byte 길이 + 문자열`, `2 byte 길이 + 문자열`) → 선택해서 규칙에 추가
- 문자열 목록 (앞 3 byte 함께 표시, 더블클릭 → hex 위치)

적합도는 "얼마나 많은 byte 를 오류 없이 설명하는가"에 기반하며, 1 byte 짜리 항목만 잔뜩 나오거나
최상위 객체가 여러 개인 해석은 잡음으로 보고 점수를 깎습니다.

## 명령줄 (`btt.exe` 또는 `python -m binarytotext`)

```
btt decode 파일 --rules 규칙.json [-o 결과.txt] [--no-offsets] [--raw] [--json] [--no-labels] [--no-quotes] [--commas] [--layout lines|arrays|inline]
btt decode 파일 --library 규칙폴더 -o 결과.txt   # 식별 조건으로 규칙 세트 자동 선택
btt decode 파일 --format protobuf --opt nested=true --pre zlib
btt batch 폴더 -r --include "*.bin" --library 규칙폴더 --rules 기본.json -d 출력폴더 --name "{stem}_해석.txt"
btt batch a.bin b.bin "logs\*.dat" --format msgpack --json   # 출력 폴더를 안 주면 원본 옆에 저장
btt analyze 파일
btt formats            # 내장 포맷과 옵션 목록
```

## 포맷 추가하기

`binarytotext/formats/` 에 모듈을 만들고 `register(Decoder(...))` 를 호출한 뒤
`formats/__init__.py` 에서 import 합니다. 디코더는 `Node` 트리를 돌려주면 되고, GUI 옵션 화면과
자동 분석은 등록 정보로 자동 구성됩니다.
